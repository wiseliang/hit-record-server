# 验证任务的资源与超时保护

浏览器验证必须通过受控入口运行。资源不足或已有验证占用锁时，立即返回原因；不要重复启动同一测试。

## 常用命令

- 防卡死回归：npm run test:guard
- 浏览器回归：npm run test:browser
- 自定义任务：python3 scripts/run-guarded.py --timeout 180 --label check -- command arguments

跨前后端仓库、工作树运行时，设置同一个绝对路径 RECORDER_VALIDATION_LOCK，确保共用串行锁。当前工作区的 .runtime/v18-checks.py 是本地联调入口，依次执行所指定的检查，失败后停止。

## 运行机制

- 从 /proc/self/cgroup 读取所属 cgroup，再读取任务数和内存限额；不能只读取 /sys/fs/cgroup 根目录。
- 默认至少保留128个任务容量及384MiB内存余量，容量不够时不启动子进程。
- 排他锁不排队等待；已有任务运行时立即返回73。
- Linux subreaper 接管本任务脱离进程组的后代，包括 Playwright 分离启动的 Chromium。
- 追踪 PID 与进程出生时间；只清理本次任务的后代，防止误伤复用的 PID。
- 到期或收到终止信号后，先终止，再强制杀死剩余后代并回收。
- 不通过 stdout PIPE 等待日志排空，避免后代持有管道导致父进程等待不结束。
- 默认每15秒输出心跳；--log 保存私有日志，--proof 保存脱敏运行结果。
- 清理后仍有存活进程时返回76，不能将其当作验证通过。

## 退出码

0 成功；73 已有验证占锁；75 资源不足或无法启动；76 清理未完成；124 超时；130 被中断。其他非零退出码来自被验证的程序。

超时属于失败。故障注入测试预期返回124时，应额外核实 timedOut 为 true 且 remainingProcesses 为0。

## 覆盖的故障测试

正常退出、忽略SIGTERM的分离子进程、主进程成功但留下分离后代、任务容量不足、内存容量不足、同锁重复启动、用户中断清理。

本保护约束本项目测试流程，不提高宿主服务配额。它不能阻止同一服务中其他无关任务自行消耗资源；实际可用余量不足时应明确失败，不能无期限重试。

## 分步骤定位

浏览器池分别记录launch、connect_cdp、create_context、create_page的开始、完成、失败与elapsedMs；不记录Cookie、验证码、学生信息或完整URL。单次浏览器启动和CDP连接显式限制20秒。页面联调的单次操作、导航、总任务分别按10秒、15秒、90秒控制；这些测试限额不直接套用到后台全量成绩同步任务。
