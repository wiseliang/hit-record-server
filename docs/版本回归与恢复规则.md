# v1.4.3 版本回归与恢复规则

日常操作保持「选择范围 → 设置规则 → 核对录入」。学校重新认证返回同一页；重新读取和回查不会提交记录。正式提交始终需要原确认按钮。

## 自动检查范围

| 风险 | 自动验证 |
|---|---|
| 校历周次错误 | 从学校同步校历；限定本学期、对应周，禁止更改服务器校历 |
| 学情与工作日志名册混用 | 各自来源、精确学号、跨账户访问拒绝、外来学号拒绝 |
| 时间违规 | 工作日、白天、排除日期、活动结束已过去、滚动十分钟最多两人 |
| 重复写入 | 请求幂等、已存在跳过、提交前最终校验、唯一保存回执 |
| 保存响应丢失 | 未确认项只读回查；仍未确认时暂缓相关学生后续项 |
| 中断后的重试 | 先回查原任务，再重新读取名单和学校记录；复用原活动时间，进入预览确认 |
| 重试读取中断 | 后台异步检查、失败或取消不能提交，服务重启标记 interrupted |
| 连接失效 | 明确阶段绕过一分钟验证缓存；临时学校故障保留已存连接和保留期限 |
| 任务结果误读 | 完整与轻量结果计数一致；已有、未安排、未执行、失败、待回查分别展示 |
| 长名单和草稿 | 搜索空格/大小写、隐藏选择保留、名单变化剔除外来学号、各入口隔离 |

## 必须通过的发布检查

1. 服务端 `npm test` 与 `npm run check:syntax`。
2. 仅用独立 `_stage`/`_test` 库执行 `npm run test:integration`。
3. 服务端 `npm run test:browser`：Chromium 上下文隔离、学校保存回执、表单复用守卫。
4. App `npm test` 与 Android export；CI Android 构建必须成功。
5. 同组件手机尺寸浏览器验收：连接提醒、过期自动重读、草稿恢复、重登返回、提交仍手动确认、断网进度恢复、长名单筛选、两类名单分离。
6. APK 校验版本号、包名、签名、生产 API；部署前确认无活跃任务/扫描，并备份；部署后验证发布页、所有资源、完整公网 APK 和分段下载。

已有 GitHub Actions 会自动运行各仓库的单元/集成/浏览器回归与导出构建。测试不能替代 Android 手机安装、原生日期控件、键盘与后台生命周期的实机验证。

## 恢复的保守边界

未取得唯一回执不等同于未保存。回查仍不确定时，不自动重写该项，也不释放相关学生的后续项。仅对已确定失败或未执行的项建立新的只读预览，随后仍由用户确认。跨学期不套用旧任务。

学校会话最多保留 24 小时，复用和恢复现有 Cookie；不承诺绕过学校验证码或在学校撤销会话后静默续期。失败不会延长原会话保留期限。

学情“仅看待录入”读取各所选周、对应入口类型的已有记录；这会比只读姓名增加学校请求，并发限定为 2。保存前仍独立重新核对，不能用列表次数替代最终检查。

## 性能观测

日志仅保留任务编号、业务类型、阶段耗时、RPC 数与错误数。新增导航与学情最终校验阶段；学校读取、初始工作日志快照、保存与回查也有阶段统计。累计 RPC 耗时和嵌套阶段耗时不能直接相加作为总耗时，不能据此承诺整批任务的速度提升。
