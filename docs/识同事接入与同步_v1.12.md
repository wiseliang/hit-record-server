# 识同事接入与同步（v1.12 开发版）

本功能将学校登录后的用户接入识同事个人库，不要求预注册识同事账号。默认关闭跨服务连接，未配置时原功能继续使用。本文件描述新代码，生产仍需配置、迁移及验证。

## 运行配置

学工后端：

```dotenv
STAFF_FINDER_URL=http://127.0.0.1:3086/
SCHOOL_BRIDGE_ISSUER=student-recorder
SCHOOL_BRIDGE_SECRET=<独立生成的至少32字节随机密钥>
```

识同事后端配置相同的 SCHOOL_BRIDGE_ISSUER、SCHOOL_BRIDGE_SECRET。这些是后端配置，不能写到 Expo 公共环境变量。远端地址必须HTTPS；回环允许HTTP。公网子路径地址示例为 https://wiseliang.cloud/staff-finder/，代理需保持现有剥离子路径规则。

每次内部请求使用有效期45秒的签名声明，绑定issuer、subject、audience、method、上游内部path及JSON body哈希，包含一次性jti。subject来自school_account_bindings中已验证身份，不接受客户端任意指定。识同事验证并持久拒绝重放，首次原子创建普通内部账号和专属学生库。内部账号没有通用注册密码。

App仍使用原Bearer登录，识同事Cookie只保留学工后端内存，7小时重新交换；不会传给App。已有识同事本地账号可输入原凭证显式绑定；绑定会转移学校来源库并撤销临时内部身份会话，原本地库不变。

## 新增持久化表

学工启动在原迁移完成后，创建 recognition_settings、recognition_consents、recognition_consent_events、recognition_jobs，均为增量表。worker每秒领取一个pending任务，同一来源只能有一个活动任务；工作租约300秒，服务中断后过期任务转paused，手动继续会使用来源键核对已提交结果。

识同事新增 external_identities、external_members、bridge_nonces。学校来源库的普通写接口只读，恢复、删除、导入也不能绕过同步授权；原手工库保留现有行为。

## API

以下均挂在 /api/recognition，要求原App Bearer：

- GET /state：当前配置、本人范围、逐人授权状态和最近任务。
- POST /check：已有用户开启自动检查后，最多每6小时启动一次同步；App登录恢复调用，不强迫弹配置窗口。
- POST /bind：{username,password}，可选原识同事账号验证绑定；不返回Cookie。
- POST /consents：{confirmIndividualConsent:true,items:[{studentId,active,reference}]}。授权仅限当前所带学生；撤销支持历史已记录人员。每条授权记录需要可核对引用。授权用途为人脸识别，学校图片查看权限不代替本人用途同意。
- POST /sync-jobs：{enabled:true/false,refreshPhotos:false}。创建或返回活动任务；默认复用照片缓存，refreshPhotos为true时重读源照片。每任务保持一个递增范围版本。
- GET /sync-jobs/:id，POST /sync-jobs/:id/pause，POST /sync-jobs/:id/resume：本人任务进度、安全暂停和继续。授权变化会取消旧任务，需新建。
- POST /search：{image:JPEG base64}，图片最长建议1280，base64小于3MiB。只查询，不保存查询图。
- GET /people/:id：受保护档案；仅在当前来源和权限匹配时附带学业档案跳转。
- GET /people/:id/photo-data?photoId=...：鉴权照片data URI；另保留二进制photo及photos/:photoId接口。

识同事内部 /internal/v1/school 下的exchange、scope、members、revoke、reauthorize均使用签名JSON请求，不接受客户端Bearer充当内部认证。

## 范围与失败恢复

完整所带名单和逐人有效授权的交集才参与同步。先提交完整授权范围，再发送照片。学校刷新、分页失败、身份不一致时，不把异常当作清空名单。普通名单变更接口会尝试排入范围核对任务；实际同步也核对当前名单。

撤销先保存学工授权，再更新识同事本地状态，让记录退出检索；云端删除失败列为cleanupPending。受保护档案、照片及检索候选返回前仍核对当前来源授权，避免后台尚未完成时返回旧候选。已有明确共享库继续遵循原ACL。

同步按学号匹配，来源映射与照片保存同事务提交；云请求结果不确定时保留pending供后续同一来源键重试，不重复创建。照片哈希未变化仅更新资料，不重复建库；拒绝同来源内多人完全相同的照片，提示核对默认图。重复照片哈希不证明身份一致。

暂停在单行安全边界发生；已执行的云操作不冒充已回滚。认证过期进入awaiting_auth，需要本次VPN/CAS及验证码流程。一个人照片不合格允许其他人继续；连续网络错误暂停。

## 验证与部署

先在独立数据库运行迁移和集成测试，禁止对生产执行schema.sql。保持原加密密钥和云库映射。先部署兼容的识同事3.4后端，再部署学工1.12后端，配置独立桥接密钥，最后更新App。停服务前暂停新同步worker并确认原有录入任务guard；新增云操作需要跟踪映射，数据库回滚不会自动回滚云端。

Android需重新构建原生包以加入拍照/裁图模块，保持原包名及签名，versionCode高于线上。开发版暂定1.12.0/19，发布前重新核对线上最新版本。不使用JavaScript导出代替APK验收。先用合成照片和云替身，再进行已获授权的小范围真实试点。

部署任务guard需将健康接口新增的recognitionWorkers计入活动工作数，并在切换前停止新同步领取。学校来源库的issuer应长期稳定，密钥轮换不应顺带变更issuer。

范围撤销与云端清理分离：scope/revoke先提交本地退出检索，随后由同步worker调用cleanup每次最多清理3人，避免大范围调动长时间占用写锁。cleanupPending保留在任务中，可继续任务分批清理，未清理云索引也不能返回本地已退出记录。名单变更会取消旧同步版本并排入核对任务。

授权变更在同一MySQL事务中追加recognition_consent_events历史，记录操作者、人员、授权引用及授予/撤销状态；当前状态与历史记录分开保存。

学工1.12另提供教务会话复用和官方信任设备优先策略，配置SCHOOL_PREFER_TRUSTED_DEVICE（默认true）及ACADEMIC_SESSION_RETENTION_HOURS（默认24）。任务created_at/updated_at升级到微秒精度，避免同秒任务状态排序歧义；保留现有时间类型和旧数据，须在无活动写入任务时迁移。
