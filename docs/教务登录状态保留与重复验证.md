# 教务登录状态保留与重复验证

本次依据学工v1.11代码及学校官方说明排查，未读取其他项目的生产认证日志，未向学校提交登录、验证码或真实学生查询。

## 已查到的应用侧原因

- 活动教务浏览器上下文空闲15分钟释放，最长2小时；这是服务器资源策略，不等于学校会话必然失效。
- 旧版加密教务快照固定保留1小时，业务成功后不更新，因此可能在学校Cookie仍有效时丢失可恢复状态。
- 旧版点击连接会先销毁旧活动上下文；恢复未读到教务页时，直接清除恢复上下文重新走VPN，未尝试仍有效的官方SSO。
- 网络超时、学校5xx与登录失效未充分区分，可能把暂时服务异常当作需要重新认证。
- 后台首次使用教务会自动发起连接，可能主动请求验证码；用户重复点击连接还可能创建新挑战。

这些代码行为会增加重新验证的机会，但不是对用户每一次验证码原因的生产实测结论。

## 本次修改

1. 连接按钮先核验并复用同账号有效活动连接；当前验证码挑战保留，不因重复连接重新申请。
2. 教务快照继续使用既有加密与按账号隔离，默认保留24小时，`ACADEMIC_SESSION_RETENTION_HOURS`可设1～168。仅在登录核验或业务成功后刷新Cookie和快照保留期。
3. 子系统失效时仅尝试已有官方CAS登录签发的单次票据，经正确VPN入口消费，必须再次验证受保护教务页后才认为恢复成功。不会用已有票据重复跳转，也不把302或200等同认证成功。
4. 学校超时、5xx、429按暂时不可用返回，保留可恢复状态，不直接转入重新认证。
5. 后台自动恢复不主动发送验证码。确需认证时提示用户进入教务连接，主动获取本次验证码。
6. 仍保留15分钟空闲释放与2小时浏览器上限，避免把浏览器常驻当作唯一保活方式；不添加定时爬取或无限请求保活。

24小时是本应用保留加密快照的上限，不是学校保证的24小时免验证码。学校使Cookie失效、要求MFA、更换账号或用户主动断开时仍按原规则处理。不要把延长本地保留期当成延长学校授权。

## 官方说明与边界

哈工大网信办《统一身份认证“多因子认证”使用详解及常见问题》（2026-03-26）说明：认证后可选择“信任此设备”；部分应用强制多因子认证；也可能由个人偏好配置触发。

来源：https://ca.hit.edu.cn/info/1146/2124.htm

哈工大网信办《统一身份认证用户使用须知》还介绍了“只能在一个浏览器上登录，只保留最新登录页面”的偏好设置。这可能影响在个人浏览器与服务器之间交替登录的体验，但本轮没有检查用户是否开启该选项。

来源：https://ca.hit.edu.cn/info/1146/1135.htm

手机浏览器与后端自动化浏览器是不同的会话环境；在手机点击“信任”不会自动为服务器建立相同信任记录。按用户最新要求，学校身份验证与教务登录均优先选择学校明确提供的“信任此设备/记住此设备”等选项；没有该选项时才选仅本次登录。配置 `SCHOOL_PREFER_TRUSTED_DEVICE=true` 默认开启，可显式设false停用。不会修改个人中心二次认证偏好，也不会跳过学校要求的本次挑战。本轮没有真实登录学校，因此尚未验证当前入口是否实际下发可持久信任Cookie。

## 验证

使用独立数据库和学校接口替身，新增验证有效页面复用、24小时加密快照、业务成功后的Cookie刷新、503/网络超时不误判失效、官方SSO单次票据恢复、重复连接保留验证码挑战。真实学校的验证码频次改善仍需上线后在正常使用中观察。

补充回归发现：任务创建时间原来精确到秒，同秒新建的照片任务可能仍显示上一条已完成记录。已把教务、照片和识人任务时间提升为微秒精度并增加回归验证，没有放宽生产限流。
