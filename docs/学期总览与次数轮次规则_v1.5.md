# v1.5.0 学期总览与学校次数、轮次规则

## 学校字段的真实含义

原来的“本周已有一条就跳过”不能表示学校要求已完成。此次按学校网页本身的显示逻辑判断两项独立要求：

- 应完成次数：`gzcs >= pc`，交接标志 `sfjjxs=1` 时，学校次数栏视为免要求。
- 应完成轮次：学校当前栏位检查 `gzlcth > 0 && gzlczf > 0 && gzlcpb > 0`，分别是谈话、走访、陪伴。次数免要求不代表轮次自动完成。
- `lc`、`lczs` 作为学校原始轮次参数保留，不把 `lczs=17` 等数值猜成“每周再录 17 条”。
- 字段缺失、空值、非整数或非法值时停止生成可写计划，不能退回“每人一次”或“零记录”的默认。

通过明确标注且随后删除的学校端测试核实：走访场景谈话同时使谈话和走访计数增加，学校工作次数增加 2；陪伴场景谈话同时增加谈话和陪伴，工作次数增加 2；独立陪伴增加陪伴和工作次数各 1。所有测试均核对唯一回执、保留原记录、删除专属测试记录，并恢复原有计数。

所以学校“计次”与本应用的“待写入记录条数”可能不同。系统先规划举措，保存前再读取学校实际计数，不能仅靠本地累加条数推断完成。

## 计划、保存和结束复核

- 一键录入继续以奇数周陪伴、偶数周谈话为优先补次数类型，同时补齐学校当前缺少的轮次举措。
- 缺走访时，使用学校实际认可的走访场景谈话；若用户所选场景不是走访类，提供“走访寝室”建议并在预览明确展示。用户应核对实际工作，必要时返回规则选择其他真实走访场景。
- 谈话、陪伴的单独入口只处理对应类型；其他轮次缺项以提示保留，不在内部要求重新选择录入类型。
- 同一学生同一周可有多条同类型记录。使用独立 occurrence 键及不同实际时间；已有一条不再阻止后续缺口。
- 保存前检查精确学号、学期周次、可编辑状态、学校最新次数/轮次、重复记录、工作时间和滚动密度。
- 学校已补齐目标时跳过；学校仍有次数缺口或本操作对应轮次缺项时才保存。未来或时间不明的既有记录先核实，不直接补写。
- 一键任务最后重新读取学校名册中的次数和轮次。仍有缺项则保留已保存回执、显示部分完成及总览入口；不会为追求完成状态无上限追加记录。
- 待回查项暂缓该学生同周的相关举措，避免因跨谈话/陪伴类型继续写入而掩盖不确定保存。

## 总览

- 工作台新增可选入口，底部导航与原三步录入流程不变。
- 学情、工作日志分别读取自己的名册。学情按逐周真实在册人员统计，不能用当前人数乘周数；工作日志使用完整所带名单。
- 学情显示已结束周同时满足学校次数和轮次的学生周数，并单列次数缺口、轮次缺项与未核实周；本周单列为进行中。
- 工作日志目标 1–10 次；按本学期已结束的有效谈话统计。未来记录不计入有效次数；学校列表累计次数单列，超额不能抵扣其他学生。
- 每类总览最多保留最近两份完整结果及当前读取状态；重新认证或切换学校连接会清理旧连接摘要，任务历史和回执不受影响。
- 第一页最多 50 人，搜索覆盖完整数据；个人明细按需返回，不把谈话长文本塞入轮询和列表。
- 同一学校连接、学期及业务分开缓存；重新认证或切换账号的新连接 ID 不复用旧学校快照。
- 默认先看带时间的已有结果，由用户发起更新，不因搜索、切页签或调整目标重新访问整学期学校接口。
- 异步读取可停止；离开或重开 App 后恢复读取进度；临时网络错误继续只读轮询，过期或学期/账号变化则停止旧轮询。
- 单周读取失败表示未核实，不是零次。新读取失败或取消，保留上次完整结果。
- 缓存跨上海周一零点会重新区分本周与已结束周；未读的新周明确标记，不延用上周为当前周或声称统计已完整。
- 从总览带入范围后，仍先读取学校最新名单和规则，生成预览并手动确认。已有预览不静默覆盖；工作日志目标和草稿能在原入口恢复。

## 学校下拉选项

谈话场景 11 项：其他、走访寝室、走访自习室、走访课堂、走访班级、走访团党支部、走访实验室、陪伴运动、陪伴进餐、陪伴自习、陪伴上课。

陪伴类型 4 项：共同进餐、共上自习、共同运动、共同上课。

选项从服务端提供的学校控件映射读取，客户端不再自由输入，服务端也校验选项；保存时仍在学校原生控件中精确选择并核对，不以未知编码替代。

## 发布完成后清理旧包

`publish-release.cjs` 只发布和更新清单；`finalize-release.cjs` 必须在生产服务、发布页及完整 APK 公网下载验证通过后执行。

示例（实际路径由当前项目提供）：

```
RELEASE_ARTIFACT_ROOT=项目根目录 RELEASE_DOWNLOAD_DIR=公开下载目录 node scripts/finalize-release.cjs 公网验证结果.json
RELEASE_ARTIFACT_ROOT=项目根目录 RELEASE_DOWNLOAD_DIR=公开下载目录 node scripts/finalize-release.cjs 公网验证结果.json --apply
```

先预览再执行。清理范围限定本项目 `.runtime`、`.build-tools`、`outbox` 的已确认同包名且版本号低于最新版的 APK，以及可核实只含一个旧 APK 的专用压缩包。检查真实包身份，跳过目录/文件符号链接、上传目录、数据库备份、SDK 和其他应用，不凭文件后缀猜测。发布失败、证明与当前清单不一致或当前 APK 不匹配时不清理。当前版本及其校验说明保留；旧下载链接返回新版入口提示。

硬链接只在最后一个引用删除时计入估算释放空间，不能把逻辑删除文件大小直接当作磁盘回收量。
